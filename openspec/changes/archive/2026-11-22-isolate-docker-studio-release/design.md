# Design

## Context

工作台從工作區讀取專案、知識庫、設備設定與前端建置。Windows 既有服務在 `8018`，Docker Desktop 可執行 Linux 映像。

## Goals / Non-Goals

開發版可即時驗證，正式版可手動升級與回退。切片、CAD 和官方 Studio 保留宿主機執行方式。

## Decisions

- 使用固定 Git 提交建置 Linux 映像。Compose 只掛載正式版的 `Project`、`Context`、`Library`、`Runtime`，映像內存放前端、程式和模板。
- 映像包含由原作者套件獨立安裝的離線檔案檢查器，使容器維持待列印件檢查能力。檢查器與映像一同版本化，不受正式工作區的資料掛載覆蓋。
- 映像提供工作台的 CLI 入口與初始化配置，與瀏覽器讀取同一個正式工作區。
- 若宿主機已驗證的材料服務使用內部 CA，正式容器在啟動時把工作區指定的公開 CA 憑證加到系統信任鏈。憑證跟隨本機設定，HTTPS 仍驗證憑證與主機名稱。
- 使用 `%LOCALAPPDATA%/PrintLab` 下的獨立開發與正式資料。開發使用清空設備及憑據的測試工作區，原 checkout 保留作為搬移來源。
- 將 `10818` 綁定本機，容器內監聽 `10818` 以沿用工作台的同源檢查。Compose 以 HTTP 檢查啟動狀態。
- 平常更新須以 `tom83615` 的成功 push CI 為依據。首次開機若尚無已在遠端驗證的本機提交，使用本機提交做一次性啟用，先執行工作台 API、材料讀取、待列印及工作流程測試。候選版一律以空白工作區啟動，測試 API、首頁與首頁資產後才切換正式服務。
- 儲存上一個與目前生效的映像版本。檢查失敗時還原前一個映像。服務回退會繼續用現有正式資料。

## Risks / Trade-offs

Windows 工具路徑只能由宿主機使用。相依的本機服務若要從容器存取，端點須能由 Docker Desktop 到達。搬移以一次性複製保留來源備份，使用前核對專案和材料讀取及設備相容性。
