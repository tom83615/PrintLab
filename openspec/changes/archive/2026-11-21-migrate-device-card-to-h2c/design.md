# Design

## Context

設備卡路徑在 Python 模組、工作台與初始化腳本中分散寫死。資料本身是本機工作區設定，並非 Git 追蹤檔案；移動時必須保留其內容。X2D 亦是已驗證列印路線的實際機型名稱，不能全域替換。

## Goals / Non-Goals

**Goals:**

- 將唯一的目前設備卡明確放在 `Library/Devices/H2C/`。
- 所有設備卡存取及文件入口改用新路徑。
- 保留既有 X2D 機型支援字串、設定和流程。

**Non-Goals:**

- 建立多設備選擇或 A1 設備卡。
- 將 X2D 切片／發送支援改為 H2C。
- 遷移其他名稱含 X2D、但屬於切片測試或機型支援的內容。

## Decisions

- 只改設備卡相關路徑引用及測試資料路徑；機型代碼與官方切片設定維持原樣。全域替換會把實際 X2D 支援誤改為 H2C。
- 既有本機 `device.json` 與 `installed.md` 原樣搬到新目錄；初始化流程也建立 H2C 路徑，避免新工作區重新產生舊名稱。
- 以程式碼中的單一路徑常數供各 Harness 模組使用，工作台與文件則使用新路徑。

## Risks / Trade-offs

- 使用者可能有外部腳本依賴舊路徑 → 此倉庫內部引用全部更新；不保留舊目錄副本，避免出現兩份可分歧的設備卡。
- 單一設備設定仍是目前限制 → 本次只把它命名為實際 H2C，不宣稱支援多設備管理。

## Migration Plan

1. 將本機設備資料搬到 `Library/Devices/H2C/`，確認檔案內容一致且舊路徑不再存在。
2. 更新程式、測試、初始化流程和文件引用。
3. 執行相關回歸驗證；若需回退，將設備檔案搬回舊目錄並還原路徑變更。
